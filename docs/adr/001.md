# ADR 001：分诊用 workflow，根因调查用 agent

- 状态：已接受
- 日期：2026-11-12

## 背景

告警分诊的输入输出固定、频率高、对延迟敏感；根因调查的路径无法事先枚举（要看哪个服务、查哪种信号取决于中间结果）。

## 决定

分诊实现为固定 workflow（单次 Haiku 5.5 调用 + 结构化输出）；只有根因调查使用 agent 工具循环（Opus 5.5）。

## 备选方案

全程 agent：成本和延迟高，行为难预测。全程固定 workflow：无法覆盖未知故障。

## 后果

分诊可以用确定性测试覆盖；agent 部分需要端到端评估和轮数、预算上限。
