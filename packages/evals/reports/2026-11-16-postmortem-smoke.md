# 复盘提示冒烟评估（2026-11-16）

ADR 011 新增的复盘起草步骤的第一次评估。配置：提示 `postmortem@1`，`claude-sonnet-5-5` / `medium`；调查用 `claude-opus-5-5` / `high`，回放模式，真实检索；judge 为 `root-cause-rubric@2`。命令是 `evals postmortem-smoke`，取前 3 条非合成的冒烟故障用例。

## 结论

**3 份草稿的「根因」一节都采用了响应者给出的根因（3/3），没有一份把未执行的处置写成已执行。** 这是冒烟级别的证据：样本只有 3 条，下面列了它没有覆盖的情况。

| ------------- | ------------ | ---------------------- | ---------------- | -------------------- |
| `fc-112fd080` | completed    | match                  | 0.2975           | 0.0230               |

| `fc-4748e676` | completed    | match                  | 0.1618           | 0.0168               |

合计 0.77 美元，其中草稿和 judge 0.06 美元。

## 每条用例做了什么

1. 回放快照跑一次调查。三条都提出了处置建议，停在 `awaiting_approval`。
2. 评估拒绝全部待审批的提议（不执行任何操作），调查变为 `completed`。
3. 把用例标注的根因作为响应者反馈提交（`rating: down` 加 `actualRootCause`）。
4. 请求复盘草稿，由 judge 判断草稿的「根因」一节和标注根因是否一致。

## 人工阅读草稿

judge 只看根因一节，其余部分是人读的（3 份全文在运行机器的 `output/postmortem-smoke.json`，不入库）：

- **处置**：三份都写明「没有执行任何处置」，并说明调查提议的 ToggleFlag 被拒绝、效果未知。没有臆造执行结果。
- **根因的归属**：三份都把响应者的说法放在前面，把调查的结论标成「调查的推断」。`fc-112fd080` 和 `fc-1e173a08` 里，草稿因为反馈是 `down` 而写「flag 的归因不应视为已确认」。这是评估固定提交 `down` 造成的：标注根因其实和调查结论一致，草稿却读成了响应者不认可调查。真实使用中 `down` 加根因确实表示不认可，所以这不算提示的缺陷，但说明评估的输入不够自然。
- **现象**：时间、指标和日志都来自调查报告里的证据，没有发现报告之外的事实。

## 没有覆盖的

- **调查结论错误时的表现。** 三条用例里调查都找对了方向，所以「人工根因与调查结论冲突时以人工为准」只被弱验证了。需要一条调查失败或结论错误的用例。
- **没有反馈时的草稿**，以及有已执行处置（批准并执行成功或失败）时「处置」一节的写法。
- **judge 没有为复盘校准。** `root-cause-rubric@2` 校准的对象是调查假设，这里用它判断一段更长的文字，可能偏宽。
- 样本只有 3 条，不能给出比例意义上的结论。
